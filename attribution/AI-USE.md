# AI-use declaration

**Group 6 · VeriFin: Evidence-Grounded Financial Research with Structured Verification**

We used OpenAI Codex during development and submission preparation. Codex helped compare orchestration approaches, implement and review the experimental LangGraph backend alongside the Python baseline, write and diagnose regression and replay checks, organize experimental evidence, and draft project documentation and submission material. This preparation used Codex with GPT-6.2 Sol and GPT-6.2 Astra where the session records identify those models. Historical records identify Codex but do not consistently identify the exact Codex model. An older team-only ticket-intake experiment also used Codex CLI to interpret natural-language requests and settings before the host validated them. That integration is outside the submitted application.

VeriFin itself uses generative models for planning, drafting, and claim-by-claim verification. GPT-6.1 Sol (`gpt-6.1-sol`, OpenAI Responses) was used in development pilots, follow-up tests, and the four-condition E1 work. Qwen3.7-Plus (`qwen/qwen3.7-plus`) and DeepSeek V4.1 Flash 1017 (`deepseek/deepseek-v4.1-flash-1017`) were used through OpenRouter in development pilots. Qwen3-32B (`qwen/qwen3-32b`) was used in a separate live orchestration follow-up probe. For E1, the same model can also act as the generic reviewer or revision planner. Local embedding and reranking models used in component studies are listed in [Third-party attribution](THIRD-PARTY.md). Model choices and budgets vary by run. Fixed historical model receipts or explicitly scripted receipts supplied some offline tests, where the tools and state could still execute locally.

Codex also applied the development pilot rubric to user-visible answers. That rubric distinguishes correct amounts and source locations, gaps, and failures. A model performing Structured Critic review is part of the evaluated system. A Codex grade is a separate AI assessment. The retained pilot records do not establish an independent human check or the proposed two-person annotation on a new event holdout. The pilot grades are disclosed as development diagnostics.

The prompt record includes the complete static role prompts of the submitted application, verbatim public development task inputs, and retained excerpts from Codex development instructions. Earlier development dialogues, per-run historical role inputs, ticket-intake prompts, and standalone judging prompts are incomplete in the retained submission materials. [Prompt record](PROMPTS.md)

Group 6 is responsible for the accuracy of the source, experimental claims, attribution, and report, and for explaining the AI-assisted work. No new paid research-model requests were made to prepare this disclosure.
