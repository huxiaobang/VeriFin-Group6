# 工具结果改用同一请求内的引用，会影响什么

**完整角色视图中，八个冻结状态有六个能减少请求体；显式缓存的公共前缀和断点均保持原样。** 对每个状态取一次完整角色请求，合计减少 **41,118 个 UTF-8 字节**。15 条证据和 1 条计算的原工具字段均可从实际待发送的请求体还原。八个状态的短视图 Planner 本身已经用最近工具结果的指针，本次变更对其请求体的额外节省为零。[逐请求结果](重复引用的请求影响.json) · [此前的上下文级测量](重复原文回放.json)

**可执行的接入位置是在确定角色最终可见视图后，比较同一请求中的字段。** 完整视图能满足判重条件。旧会话若缺少 `recent_tool_results`，先在完整视图去重、再生成短视图，可能把唯一的完整工具结果换成只指向预览的 ID。本地用航空状态复现了 3 个这样的引用。按短视图最终可见内容重做比较，3 段都保留全文。[反例与请求构造脚本](重复引用的请求影响.py) · [Planner 视图实现](../../VeriFin_Code/verifin/context.py)

## 模型能从哪里找到记录

| 待发送布局 | `same_record_in: evidence` 的实际位置 | `same_record_in: calculations` 的实际位置 |
|---|---|---|
| 显式 Responses | 前部有单独的用户消息，每条证据块写明 `Entry in context.evidence` 并携带唯一 ID 和原文；此时最后一段 JSON 本身没有 `evidence` 数组 | 最后一条用户消息里的 `context.calculations`，按 ID 找到数值、公式及操作数 |
| 普通 Responses、Chat、显式布局未启用时的回退 | 最后一条用户消息的完整 JSON 内，按 `evidence` 数组及 ID 找到 | 同一 JSON 内的 `calculations` 数组 |
| 短视图 Planner | 八个当前状态的最后结果均已写成 `see: episode.recent_tool_results[-1]`，原件是否可见取决于当前角色展示的正文或预览 | 沿用现有最近结果的计算 ID；在这些状态未产生新的引用 |

16 个原工具条目均未附存储侧版本号。还原程序按“组＋ID”在**当前请求**中找记录，并用 `omit_fields` 排除后来加上的存储字段，恢复工具当时有的字段。证据条目排除 `created_at/stale/version`，计算条目排除 `created_at/version`。按源字段确实可逆，模型是否理解这些键、能否正确追到先前独立的证据消息、能否保留刚返回值的注意力，仍未经行为验证。若写接入说明，可把“找同组同 ID 的可见记录”的一次性说明放到最后一条用户上下文消息，避免改变共同工具定义或以往的任务断点；这个说明本身未计入上面的字节差。[实际分块代码](../../VeriFin_Code/verifin/model.py) · [还原函数](重复原文回放.py)

## 历史与版本反例

- **同 ID 明示不同版本。** 将航空工具条目的版本设为 1，当前记录设为 2 并更改正文。完整视图保留版本 1 的原结果，版本 2 的记录仍单独可见。再将两个正文改为相同，仅版本不同，仍保留旧结果。若旧工具条目本来没有版本，其他原字段又逐项相同，当前实现会引用并从还原结果剔除后加的版本字段。它能还原工具原始载荷，无法证明旧事件实际来自当前的存储版本。[反例实测](重复引用的请求影响.json)
- **现有短视图还有独立的版本边界。** 在上面的同 ID、不同正文／版本反例里，保留 `recent_tool_results` 时，现有短视图主要比较 ID 列表及 summary／ok／data／error，未比逐条正文与版本，已会折叠旧结果。该次请求的最近结果只剩 ID，当前索引显示版本 2。新增的完整视图判重并未造成此行为；若短视图也要承诺历史值可复原，现有这道判断也需要收紧。[短视图现行判断](../../VeriFin_Code/verifin/context.py)
- **缺少最近结果的旧 checkpoint。** 从航空状态移走 `recent_tool_results`，其余字段沿用冻结记录。原短视图会在最后工具结果保留 3 段原文。先去重再生成短视图，3 条前部记录都变为没有全文的预览，最后结果又只剩引用，因而已无法在请求内还原。按最终可见视图判重可以保留这 3 段，避免新增检索。[逐条丢失字段](重复引用的请求影响.json)
- **缺字段和歧义 ID。** 历史状态缺整个 `calculations` 或 `evidence` 数组时，当前实验函数抛 `KeyError`；组内重复 ID 时抛 `ValueError`。若接到产品请求，可只在源组结构完整且定位唯一时去重，否则沿用原载荷。某些旧 episode 连 `last_tool_result` 都没有，简单照搬“取空字典再赋回去”会凭空增加字段，应保留缺失状态。[历史兼容性用例](重复引用的请求影响.py)
