# 四个案例中，Agent 实际重复了什么

**当前不宜把 DSH 的相同调用提醒接入默认流程。** 固定的 33 份原始事件导出中，39 个有工具调用的 episode 共执行 112 次。同一 episode 内，即使把中间隔着其他动作的调用也算入，工具名和全部参数相同的重做仍为 **0 次**。把这 112 次按原顺序送进 DSH 的实际处理函数，默认提醒命中 **0 次**。三次搜索确实再次取回已有段落，但每次也各带回 2–4 段新材料。把其中任何一次整项省掉都会丢材料。[逐文件哈希与证据坐标](工具重复核对.json) · [上游原函数实测](重复守卫原函数.json)

| 案例 | 事件导出 | 有工具的 episode | 工具调用 | 文档搜索 | 检索返回段落 | 同轮已返回的原样段落 |
|---|---:|---:|---:|---:|---:|---:|

| HOG | 5 | 5 | 11 | 4 | 18 | 0 |

## 固定官方源码实际做了什么

Harness `39163dd30f703a79079e2d2446545cff3c453738` 的 `repeat-tool-reminder` 以每个 Agent 为单位。它递归排序对象键，保留数组顺序，用工具名与完整规范化参数形成键。默认所有工具参加，同一键连续第 3、5、8 次才产生提醒。不同的受跟踪调用会重置链，用户新输入也会清空该 Agent 的链。通过 include/exclude 排除的调用对链透明。提醒发生在 `tools/post-execute`，下游执行决定和返回值保留。其 `observe` 没有查看语料、结果段落或查询意图。[默认设置](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/guard/repeat-tool-reminder/src/index.ts#L35-L56) · [规范化](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/guard/repeat-tool-reminder/src/index.ts#L88-L112) · [观察和提醒](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/guard/repeat-tool-reminder/src/index.ts#L180-L232)

离线探针直接加载固定 Git 对象对应的 TypeScript 模块并调用 `apply`。只替换 schema 声明和创建带标签消息的外壳，显式传入默认配置，每个 VeriFin episode 对应独立 Agent 对象。真实轨迹零提醒。阳性对照用真实参数重复 8 次并交替倒排顶层对象键，原函数恰在第 3、5、8 次提醒。中间改变 `limit` 或模拟一条用户输入均重置链。本次验证范围为该处理函数和上述生命周期映射。[本地探针](repeat_guard_probe.mjs) · [上游默认阈值测试](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/guard/repeat-tool-reminder/tests/repeat-tool-reminder.spec.ts#L67-L86) · [上游独立 Agent 与用户重置测试](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/guard/repeat-tool-reminder/tests/repeat-tool-reminder.spec.ts#L203-L259)

VeriFin 引擎在工具完成后以工具名、参数、剔除耗时和评分等易变字段后的结果判断进度。成功且此前未见该组合即算进展。检索器返回每个命中及本次得分；存储层忽略仅有评分、检索时间的差异，能保持原证据版本。因此异参搜索重新命中同段的直接可观察后果在工具观察及其内容投影，不能据此声称证据库又建了一份记录。[进度计算，engine.py 第31、391行](../../VeriFin_Code/verifin/engine.py) · [检索返回，retrieval.py 第244行](../../VeriFin_Code/verifin/retrieval.py) · [证据版本，storage.py 第537行](../../VeriFin_Code/verifin/storage.py)

## 可落地的选择

**保留离线“新命中／已见段落”核对，供开发者定位长工具结果。** 同一 episode、有效过滤条件、语料指纹、来源、文档与段落 ID、原件及提取文本哈希、字符区间和正文都一致才计入。十段全部逐一重新打开本地固定快照，核对原件哈希、提取文本哈希和切片后还原的完整当前记录。重复命中仍保留本次排名和评分。九个离线变体覆盖内容等长但不同、来源版本变化、坐标或截止时刻变化、结构化单元格等。[逐段记录与边界测试](工具重复核对.json)

累计 **17,217 个 Unicode 字符**位于这些再次返回的旧段内。这是工具响应正文的重合量。当前 Planner 已另有证据索引视图，实际模型请求可能含摘要、去除重复载荷或因角色而带全文。因此这组数不能换算为可省 token、费用或模型调用。若后续真实请求记录显示旧段仍反复占据角色输入，可在该角色当前可访问同一原文、且能重开时，单独实验只将重复段显示为出处和排名，保留所有新段、显式读窗及原始工具回执。本轮为离线核查，正式引擎未改动，项目模型 API、Reportify 均为零调用。[现有视图，context.py 第140–167行](../../VeriFin_Code/verifin/context.py)
