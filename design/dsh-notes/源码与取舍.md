## 1．工具执行结果如何留下

**Harness。** 工具按声明的输出 schema 返回 JSON。执行管线验证其值，再生成模型内容和可选展示元数据；替换内容的策略保留原值，策略换值则重新验证和投影。执行期的 `value` 明确不随原生工具结果事件持久化。批量执行器为发起动作和结果分别追加事件，结果携带调用 ID、模型内容、失败标志、可选错误信息和展示元数据，并指向发起事件。用 UI 卡片或模型消息回读时，只能取回当时持久化的字段。[结果接口](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/core/tools/src/contracts.ts#L339-L350) · [执行管线](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/core/tools/src/pipeline.ts#L557-L595) · [事件落盘](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/core/tools/src/batch.ts#L242-L268) · [投影测试](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/core/tools/tests/tools.spec.ts#L454-L500)

**VeriFin。** 现有引擎保存工具公开返回的 `data/evidence/calculations/error`、观察哈希、摘要和成功标记。来源快照和字符位置可再定位原文；这一层比只保存角色看到的摘要更适合审查数字。航空父报告事件 #130 的美联航段落被完整取回。事件 #138 也能取回，仍报告运算数缺少指标定义。引用段落的 ID 和可以计算的表格单元格 ID 须区别呈现。[引擎](../../VeriFin_Code/verifin/engine.py) · [原案例错误说明](../../VeriFin_Sol对照/航空第三轮_修订反馈实测/对照结果.md) · [已恢复的三条观察](离线故障注入.json)

## 2．不同角色需要读多少上下文

**superagent。** Sessions 为主会话与 worker 选择不同 preset，worker 有独立工具列表。路由消息保留工单状态、ID 和读取完整结果的路径。完成报告超过 600 个 JavaScript 字符串代码单元时，router 的消息只有开头、原长度和 `ticket/<id>/result`。没有回答问题的普通进度报告留在 worker。官方测试断言摘要长度、重开路径和卡片中的重复预览都符合约定。router 仍有部分读取和 shell 能力，角色提示并不等同于访问隔离。[角色与工具](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/src/app/sessions.ts#L48-L65) · [摘要与重开路径](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/src/app/notices.ts#L107-L128) · [路由断言](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/tests/tools.spec.ts#L402-L420) · [角色能力说明](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/docs/007-architecture.md)

**VeriFin 推断。** Planner 可先读证据 ID、发行人、期间和重开定位；Researcher 与 Structured Critic 仍要看到原记录、单元格表头和算式。单点目标是减少 Planner 重复读长段落，具体是否节约 token 或影响查证次数，由同题实测判断。当前 Planner 视图对有 `read_document` 能力且具备文档坐标的段落建立索引；显式重开的一次返回保留正文。对没有重开路径的内容，压缩会降低可核验性。[Planner 原型](../../VeriFin_Code/verifin/context.py) · [核验代码](../../VeriFin_Code/verifin/verification.py)

**反例。** Harness 可选 pruner 默认超过 8,192 个 Unicode 码点才保留前 4,096 和后 1,024 个码点，并记录替换源事件。我们按此规则对已存的工具观察使用明确的紧凑 JSON 渲染。航空两次选格分别为 6,069 和 6,540 字符，均不触发；GM 的 15,596 字符缩至 5,159，能直接看到的候选 ID 由 12 减为 4。历史原题所选两格都还在，但集团季度 EBIT-adjusted margin 的 5.3% 和 4.1% 两个 ID 都消失。该测量是字段可见性的离线反事实，未用新模型回答 GM 追问，也没有测出因此产生的 token 费用。[上游默认参数](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/compaction/compaction-tool-result-pruner/src/config.ts#L7-L16) · [持久化替换断言](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/compaction/compaction-tool-result-pruner/tests/tool-result-pruner.spec.ts#L186-L252) · [逐格对照](首尾截断反例.json)

## 3．跨轮回放的边界在哪里

**Harness。** 请求形成时，循环先记录有变更的 header 和本步的请求上下文，再由事件顺序派生模型消息。表面投影只可覆盖允许的旧消息范围；替换某个工具结果时，目标必须是同一条工具结果，除内容外的身份和失败状态需保持。底层 fork 辅助函数复制到指定事件位置的前缀，加继承界标，再为该前缀中尚未关闭的调用补齐尾部。普通分支 API 对可用边界另有约束；不能凭辅助函数推断所有 UI 都允许在未完成步骤任意分支。[组装请求](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/core/agent-loop/src/agent.ts#L672-L746) · [替换约束](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/core/session/src/surface.ts#L454-L482) · [分支种子](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/core/session/src/fork.ts#L11-L30) · [分支前后视图断言](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/core/session/tests/fork.spec.ts#L450-L470)

**superagent。** 持久状态还包括 Ticket、Assignment 和 Input。消息投递到 worker、worker 开始读取，以及完成一轮工作是三个时点。重启时重排已递送但未被工作会话读走的输入；已经读到且此后产生报告的输入保留读状态。这里区分已读与待重投输入。消息触发的远端付费操作仍需独立的执行凭证。[输入重排](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/src/core/tickets.ts#L329-L340) · [已读语义测试](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/tests/core-engine.spec.ts#L1540) · [重启文档](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/docs/003-execution.md#restart)

**VeriFin 原型。** 老数据的父报告无事件水位。原型只准读取指定会话、同 episode、报告签发前、经固定事件哈希核过的一条结果。候选分支还核对候选原文件、分支清单、父报告 ID/版本/原始 payload 哈希、分支事件和候选中对应的实际记录。一次案例原先手工挑选的两格只用于复演已提交的结果；该回放不能说明 Planner 能自主选格，也不能把父报告后来新取得的证据提前放进过去。[恢复实现](../../VeriFin_Code/verifin/recovery.py) · [原始分支清单](../../VeriFin_Sol对照/航空第三轮_从报告ID续修/branch.json)

## 4．请求结果未知时怎么办

**Harness。** 配置语义 checkpoint 插件后，模型请求在 adapter 派发前 flush，顶层工具在执行有副作用的 body 前 flush；嵌套调用共享外层边界。修复器按 call ID、turn、step 和原始追加事件匹配。只有意图记录时产出 `TOOL_NOT_STARTED`；已经记录启动而缺结果时产出 `TOOL_OUTCOME_UNKNOWN`，作为合成错误交给下一步。已提交结果不再合成。官方崩溃测试用子进程与副作用标记检查此窗口。我们运行原函数验证了这三类结果、重复修复无新增事件及分支在结果前截断的情况。原函数给模型提示，后续是否重试还取决于调用者。[持久化边界](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/session/session-checkpoint-policy/src/index.ts#L52-L81) · [尾部修复](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/core/session/src/repair.ts#L100-L197) · [上游崩溃测试](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/session/session-checkpoint-policy/tests/crash-recovery.e2e.ts#L93-L121) · [本地原函数结果](上游源码实测.json)

**superagent。** Outbox 在一次本地事务内登记发件 receipt 和发送任务，在远端发送后才将本地状态结算为 sent。GitHub 通道投递前查找同一消息标记，飞书使用幂等键。其 worker 对若干短暂网络/提供方错误最多重试三次。我们给原 Outbox 注入“模拟接收端已处理、本地首次写回失败”，手动再次运行其投递处理器。两种接收端均发生两次发送尝试，缺少去重的接收端得到两次效果，按消息 ID 去重的接收端得到一次。它说明通道契约决定副作用；不能用发件箱的本地唯一行推出付费 Critic 唯一计费。[Outbox 源码](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/src/app/outbox.ts#L25-L52) · [GitHub 通道](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/src/sources/github-channel.ts#L17-L43) · [飞书通道](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/src/sources/feishu-channel.ts#L18-L26) · [重试策略](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/docs/003-execution.md#failure-and-recovery) · [本地对照](上游源码实测.json)

**VeriFin 原型。** 只读 diagnose 给出已完成工具、可以准确重开的结果和待查账的未知模型步骤。另有独立 SQLite 步骤日志验证先登记、单一派发资格、按原尝试提交，以及中断后查询。常规 ask 循环仍按原行为将中断 episode 归档为 partial。原型未接到项目付费入口，演练没有远端计费。[命令及操作边界](恢复原型与复现.md) · [历史用量账](../../VeriFin_Sol对照/航空第三轮_从报告ID续修/cost.json)

## 采用判断

| 判断 | 结论与范围 |
|---|---|
| 可采用 | 组员可用只读命令从固定父报告/候选取回完整成功或失败观察，并给出未知回执的交接说明。使用内容哈希、原始来源和事件序号作为最小身份。 |
| 需更多验证 | Planner 索引视图须用真实角色调用核对次数、正确性、主动重开和费用。生产写路径还要把所有付费调用、预算预留和退款/回执接在同一授权流程，验证不同进程或机器是否共享唯一权威日志。 |
| 暂不采用 | 模型/供应商的通用自动重试、全文统一首尾截断、从孤立备份推定“未开始”，以及照搬 router/worker 编码工单系统。原型能减少额外执行，不能从离线数据估算各类真实中断的发生率或年度节省额。 |
