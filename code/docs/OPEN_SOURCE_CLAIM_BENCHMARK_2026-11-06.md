# FinDVer：可直接复用的金融声明核验基准

**采用为核验组件的公开基准。** 它比普通金融问答数据更接近 VeriFin 的 Structured Critic：输入是一条金融声明和原始财报，参考标注包含真假、支持段落及解释。它能显著减少从零标注二分类核验题的工作，但不能自动提供我们任意新生成答案的遗漏、因果夸大、修订回退等标签。

来源：[官方仓库](https://github.com/yilunzhao/FinDVer)、[EMNLP 2024 论文](https://aclanthology.org/2024.emnlp-main.818/)。本次下载固定到 `e8bb237def4ce555a606a45edba22666e31df248`；按实际下载文件计数，不混用论文摘要、网页或不同版本中的规模数字。

每种推理类型先按固定 seed 对报告名哈希排序，选前三个报告，再保留这些报告中全部 testmini 声明。选择在运行检索前冻结，不按得分挑题。初版按报告全局取八个会漏掉知识类，已在任何检索运行前改为上述分层规则；两版选择记录均保留。

原始表格/段落来自数据集提供的完整财报上下文，不是我们只下载或只编码相关证据。每道题仍使用它指定的原报告作为候选范围，因此没有测试“从所有公司的报告中发现正确报告”。块长不同，报告上下文字符数；不能将此结果直接与早期 600 字符块的 E3 开发结果比较。

## 必须处理的标签泄漏

跨 agent 审查实际发现：**官方 example_id 的数字区间与真假标签分段对应。** 例如 testmini 的 IE 和数值部分，0–124 全为 false，125–249 全为 true；知识部分的分段方向相反。只删除 `entailment_label` 还不够，保留官方题号或原排序也会暴露答案。

已修复并独立复核：

- 模型输入只含内容派生的不透明 ID、原始声明/完整上下文及输入 hash；不包含官方题号、subset、split 或参考解释。
- 按不透明 ID 排序导出，不保留按真假分段的原始顺序。
- 原题号、类型、分组和真假映射仅存在评分文件中；预测须绑定到相同的模型输入 hash。
- 初版 `work/.../findver/export` 标记为不可使用，未在其上运行任何模型；`export-v2` 已修复输入泄漏，最终 `export-final` 另外验证固定版本报告字节；当前脚本重建相同的无泄漏格式。

24 条有效导出逐条与当前 adapter 重算匹配，模型输入字段中没有原题号或参考字段。这个防漏处理只排除了明确的接口泄漏，不能证明公开基准没有进入模型预训练。

## 如何支持 Proposal 的 E1

推荐把工作拆成两类可解释的结果：

1. **公开声明核验组件比较。** 用这些已经标注的声明比较同模型、同原始证据、同预算下的核验方案。统一收集最终二分类判断，可自动计算 accuracy、macro-F1、覆盖率；原始真假与证据标注只给 scorer。保留每道题的反馈和失败。实际模型尚未接入，因此本次没有声明真假模型得分。
2. **自然研究输出与修订。** 原 Proposal 所说的遗漏、完整性、原因解释、冲突发现、修订是否伤害正确内容，仍需针对实际输出评价。FinDVer 的 false 不能直接当作我们六种 issue_type 的精确标签；它也没有替你标出任意研究请求的全部 required content。

有公开标注后，不需要为了开始基础数值、证据检索和二分类核验实验而让四名同学从零制作整套标签。若没有时间进行原计划的双人独立自然输出标注，最终报告应如实将该部分缩为案例分析或待验证，不把公开基准准确率改写成 E1 全部结论。已提交并得分的 Proposal 保留，最终报告说明评估数据来源与计划调整即可。

## 许可、来源与复跑

固定仓库的 [MIT 许可](https://github.com/yilunzhao/FinDVer/blob/e8bb237def4ce555a606a45edba22666e31df248/LICENSE) 与作者/论文引用已记录；财报本身仍记录发行人和 SEC 原链接，不因为代码仓库是 MIT 就重新给财报授权。发布增量包默认不内嵌全部财报或模型权重，提供固定版本下载与实际 hash。

在代码根目录：

```bash
python scripts/audit_findver.py \
  --data-dir work/public/findver \
  --output-dir work/public/findver-export \
  --download
python -m unittest tests.test_claim_benchmarks -v
```

只有 `--download` 会联网，取得官方标签、许可及固定选中的报告；省略后全程离线。`inputs.jsonl` 是模型输入，`references.jsonl` 仅给评分程序。未来预测文件是 JSON 数组，每项包含 `case_id`（不透明 ID）、`input_sha256` 和 `entailed`（true/false/null）；用 `--predictions` 评分。缺少预测及 null 均不从 accuracy 分母剔除。解释质量和 issue 分类不在这个自动分数的含义内。
