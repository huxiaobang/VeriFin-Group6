# VeriFin 开源成果采用与本轮验收

**需要改进的重点已经更具体：复用公开金融标注和成熟解析组件，用真实任务决定检索方案，并把耗时的建索引与用户的研究对话分开。** 当前并不是“已经没有可开发内容，只差你们接一个模型”。本轮已经交付公开数据适配、评分入口、结构化 HTML 解析、真实本地检索实验和可分享回放；默认 Agent 的结构摄取与索引调度仍有明确的下一步。

本报告对应源码 **v0.5.0**，保留已发布的 v0.4 归档及已提交 Proposal。没有调用付费 API，也没有把脚本或规则输出当成自主 Agent 成绩。以下是组件采用与开发证据；完整研究对话、Structured Critic 的真实效果仍需主模型运行。

## 1. 现在值得采用什么

| 资源 | 采用位置 | 本轮实际成果 | 决定 |

## 2. 实测改变了哪些判断

### 对话上下文的处理比直接换模型更紧迫

ConvFinQA **全部 1,490 轮**的公开来源块检索中，BM25 Recall@5 从仅当前问题的 **57.97%** 提升到加入此前用户问题的 **83.63%**；全部所需证据进入前五的比例从 **46.58%** 到 **71.21%**。没有使用参考答案、未来问题或模型生成的查询改写。

固定 100 轮子集的共同对照如下：

| 方法 | 只用当前问题 Recall@5 | 加此前问题 Recall@5 | 加此前问题 MRR@5 |
|---|---:|---:|---:|
| BM25 | 55.14% | 84.06% | 0.7675 |
| multilingual-e5-small dense | 59.71% | 79.46% | 0.7847 |
| BM25 + E5 RRF hybrid | 61.57% | 81.49% | 0.8073 |
| BGE-M3 dense | 53.93% | 74.85% | 0.7193 |
| BM25 + BGE RRF hybrid | 57.68% | 82.26% | 0.7587 |
| Qwen3-Embedding-0.6B dense | 57.20% | 80.70% | 0.8425 |
| BM25 + Qwen RRF hybrid | 59.20% | 81.37% | 0.8200 |
| PPLX v2 late 0.6B MaxSim | 61.35% | 83.68% | 0.8215 |
| BM25 + PPLX MaxSim RRF | 59.51% | 83.51% | 0.8177 |

这里的候选是数据集提供的完整报告片段，平均返回约 700 多字符，不是搜索所有公司的完整报告。100 轮分属 18 个来源页，有相关性。MRR 衡量首个标注证据的位置，Recall 衡量全部所需证据的覆盖，表中两者给出不同取舍。不能只选一个有利指标宣布获胜。其中1题需要7个标注块，因此top5的平均Recall理论上限为99.714%，全部证据命中率上限为99%；不把固定k造成的不可达部分算作模型独有缺陷。

三种 embedding 均实际重新编码相同 550 个原始块、162 个不同查询，使用各自官方前缀和同一评分代码。E5/BGE 文档编码分别约 3.02/24.90 秒，Qwen 约 48.99 秒；查询数字是批量编码成本，不能直接当作用户单次延迟。这里的英文 provided-context 任务没有证明“小模型容易蠢”，也没有覆盖中文问题或更大模型的能力。BGE 此处仅测 dense，不能据此评判它未运行的 learned sparse 或多向量模式。

新增的PPLX v2 late模型也已实际运行：相同550块编码146.73秒，单query编码median0.923秒，FP32文档token索引9.76MB，是同规模1024维单向量索引的约4.33倍。其MaxSim的Recall高于本轮Qwen dense，却仍未超过BM25；不同模型训练、架构、前缀和表示同时变化，不能把差别单独归因于“多向量”。本机使用CPU参考kernel，不将其速度外推为GPU/Metal表现。[模型协议、测量与复算](OPEN_SOURCE_MODELS_2026-11-06.md)

产品改进应当是：Planner 用当前 scope 和原始会话正确解析追问，再生成明确的检索请求。把所有历史无条件拼进每次查询只是本次可解释的诊断基线；遇到用户更正公司或期间，仍须避免旧条件污染新请求。

### 完整财报上，较复杂的检索没有自动胜出

FinDVer 固定 9 份完整报告、24 条公开标注声明，全部 2,971 个原段落/表格块都参与编码；每条声明在其指定完整报告内检索。

| 方法 | Recall@5 | Recall@10 | 全部证据命中率@10 |
|---|---:|---:|---:|
| BM25 | 54.10% | 67.43% | 33.33% |
| Qwen3-Embedding-0.6B dense | 40.76% | 54.79% | 16.67% |
| Hybrid | 51.32% | 65.90% | 29.17% |

这是对**公开标注位置**的召回，非标注块不一定都不相关。它不支持“较大模型普遍较差”，因为此处还没有运行 4B；它确实否定了仅凭早期十个自选问题就把当前 dense/hybrid 定为更好的做法。[完整协议、成本和失败例](OPEN_SOURCE_COMPONENTS_2026-11-06_FINDVER.md)

### 重排增加了成本，但本轮没有改善质量

Qwen3-Reranker-0.6B 对相同历史query、相同hybrid前20候选实际重排后，Recall@5从81.37%变为80.82%，MRR从0.8200变为0.7550；每题额外median4.62秒。18个来源组的配对区间跨0，不宣称统计上已证实优劣。当前没有采用默认重排的依据。[真实结果、独立核查与复跑](OPEN_SOURCE_RERANKER_2026-11-06.md)

检查退步案例还发现公开QA adapter把首行一律当表头的简化不可靠：部分表首行实际上是期初余额，序列化后出现数字列名。原始table保留且本轮方法共享同一表示，所以冻结对照仍可复算；下一轮应先修正这一表示并重新冻结数据，不能把全部退步归因模型。这比继续增加模型数量更紧迫。

### 摄取与索引不能阻塞第一次提问

这 2,971 个块的 CPU FP32 初次编码约 **14.7 分钟**，持久化向量矩阵只有约 **11.61 MiB**，峰值内存约 **2.42 GiB**。此规模的主要等待来自编码，而不是缺少向量数据库。应增加显式文档导入/预建索引任务，展示进度并支持取消；正常研究查询只编码当前 query。新的文档版本必须改变索引与缓存身份。

### 表格结构需要保留，不能靠模型猜回来

Apple R2 样本的四个收入值在旧纯文本里本来就存在。真正改善是能保留它们分别属于三个月/六个月、2025/2024 的哪一列。新模块仍保留货币符号、括号负数、百分号和缺失值原字符串。没有标记表头的长表保留整表；不能再用普通字符切分让后半表丢掉期间。

### 公开标注也必须审查

FinDVer 的官方题号区间可以暴露真假标签。已改成内容派生的不透明 ID，并打散导出顺序；官方 ID 和标签只留在评分端。原 testmini/test 有 155 个报告文件重叠，不能写成文件互斥的泛化测试。TAT-QA 的官方原始段落标注与另一个启发式处理版本的 cell mapping 也不能混称人工精确 span。

## 3. 对 Proposal 的落实方式

已经提交并得分的 Proposal 保留。最终技术报告说明哪些方案发生了调整，以及证据是什么：

- **E1：** 增加 FinDVer 公开声明核验组件比较，先用现成标签测试二分类与证据使用；自然生成答案的遗漏、冲突、原因解释和修订质量单独呈现。不能把 false 一律转成某个精确 issue_type，也不能用其准确率冒充整套 E1。
- **E2 与应用验收：** ConvFinQA 可提供多轮数值素材，但它没有标出 VeriFin 的最佳工具序列、scope 更正和重开会话行为。仍使用原有多轮验收流程测试这些能力。
- **E3：** 保留 BM25、dense、hybrid 同条件比较；分别报告 provided-context、known-report 和实际来源发现，不把三个难度层级混成一个总分。重排先报告候选 Recall@20，再报告前五结果与额外延迟。
- **技术选型：** 先保留已有轻量状态机与 SQLite。主模型 API 选择仍待真实 pilot；检索模型、解析组件、缓存策略的选择用本轮实测解释。对代码、公开数据和 AI 协助作真实披露。

## 4. 接下来应做的开发

| 优先级 | 工作 | 可由 agent 自动完成的部分 | 必须等待什么 |
|---|---|---|---|
| P0 | 公开表格表示修正 | 区分首行数据与表头，或采用不做该假设的保真行上下文；新版本重新冻结/编码/对照 | 无需人工标签或API；保留本轮历史实验，不混用新旧文本向量 |
| P0 | 结构模块进入真实工具 | 新提取版本、来源 sidecar、表格/正文选择、可追溯 evidence；旧引用不迁移错位 | 无需新人工标注；继续扩展真实格式的保真检查 |
| P0 | 摄取与预建索引 | 独立索引任务、取消/恢复、缓存身份、离线预热及查询路径 | 无需主模型 API |
| P0 | 真实多轮模型 pilot | 自动建会话、运行、留存证据/成本/失败、修复接线与行为问题 | 账号可用模型、本机凭据和支出范围 |
| P1 | 基于公开标签的核验/数值实验 | 数据准备、冻结输入、运行、客观评分与报告 | 模型调用条件；不要求先从零做整套标注 |
| P1 | Qwen 4B 量化强基线 | 官方 GGUF、llama.cpp/Metal 后端、共同数据、质量/速度/内存测量 | 下载及本机实验时间；本轮未运行 4B |
| P2 | 自然研究输出评估 | 自动准备盲审材料、归并候选问题和证据 | 若要保持原 Proposal 的独立人工语义结论，需要少量实际判断；没有就缩小结论 |

Docling 留给 PDF/跨页表格的后续需求；停止维护的 sec-parser 不作为新的主依赖。EdgarTools 保留为 SEC 语义结构候选，不能直接把其便捷数值转换当成原文证据。新闻/电话会与第二模型仲裁仍由实际失败驱动，不因为存在开源库就扩张承诺。

## 5. 验收入口

- [离线公开评测回放](../examples/open-source-study.html)：可直接转发，查看真实问题、历史、前五证据和 Apple 表格；无需 API、模型权重或联网浏览。
- `verifin-inspect-html` / `python -m verifin.structured_documents`：新的离线结构提取命令，需安装 `.[html]`。
- `verifin-public-benchmark` / `python -m verifin.public_benchmarks`：公开 QA 适配与客观评分。
- `scripts/audit_findver.py`：固定公开声明/完整报告、输入与评分标签隔离、真假评分入口。
- [模型实验](OPEN_SOURCE_MODELS_2026-11-06.md)、[数据适配与下载](OPEN_SOURCE_DATASETS_2026-11-06.md)、[HTML 解析与复跑](OPEN_SOURCE_COMPONENTS_2026-11-06.md)：各自包含固定版本、许可、命令和实际边界。
- [跨机器复跑入口](REPRODUCE_OPEN_SOURCE_STUDY.md)：源码包附带冻结选择和三种模型的真实向量，可下载固定公开数据后独立重算，无需调用主模型。

本轮额外修复 BM25 浮点累加顺序的跨进程确定性，以及并发首次打开 SQLite 时的 WAL 锁竞争。回归通过只说明实现检查结果，模型质量结论仍由上面的真实样本和独立记录支持。
