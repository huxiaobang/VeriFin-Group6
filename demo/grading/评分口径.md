# 大公司多轮开发测试的独立评分口径

在第一份新答案可见前冻结。评分单位为实际发出的每个用户轮次。财政季度以本轮截止日可获得的最后一份季度业绩公告为准；用户指明比较期时按明示期间。每轮保存逐问可见回答、公告来源、原文位置及具体退分理由。

|维度|判定|
|---|---|
|回答与引用|“完整”要求所有实质小问如实交付，核心数与单位、期间、会计口径和符号均可在原始公告复核，归因归属准确。“部分”表示至少有可用结果，但漏一小问、缺关键解释或少了会改变解读的披露。“失败”表示无可用首稿/交付、主结论错误，或把错误公司、季度、口径、因果判断给用户。资金门槛或外部中止单列；不将未执行轮次当失败。|
|概述与追问|概述核查销售与盈利方向，以及发行人明确披露且足以改变整体判断的重大事项。不同业务可采用不同代表指标。追问检查指代、是否沿用了对的公司和期间、用户要的比较或解释有无回答。择要概述无需罗列每张表。|
|证据边界|披露只支持方向或不能拆分时，答案可在清楚说明已有证据和剩余未知后得满分。完整原表明示用户所求却误报缺资料，按缺失的严重程度计分。披露发生后的原文和当前不可见资料不能充当该轮已经获得的证据。|
|查证方式|先跟踪逐问答案→主张→版本化原件或计算记录，再用本地公告全文独立定位相关行及周围管理层解释。重点复算直接决定结论的金额、增减和百分比。标注影响判断的遗漏，并给出关联原文；只从受测报告抄数字不计核实。工具诊断和原始 Critic 标签与独立判分分别报告。|
|自然性与效率|记录总角色步、工具次数、首轮审完后追加的请求，以及这些动作新增了何种影响结论的证据或文字。不同参数或工具名本身不能证明新进展。无实质增量、重复提交、为内部额外目标改稿单列；只回应一个问题的附加说明过长也可单列，不自动降正确性。|
|Skill 方法|先以原问列所需的分析动作，再看 Planner 选择、首稿实际收到的卡、使用过的证据/运算及最终句子。能证明实际应用的动作包括按照卡核对适当分母、做金额桥、按同口径区分分部/归因，或有根据地限制推断。仅在 prompt 中出现或有相关工具返回，不足以证明方法改变了答案。简单公开查询可合理不选。缺卡同时缺与用户有关的方法、选了却没有用、选用导致实质错漏、证据不足无法判别，分别计数。未放入对照或消融实验时，不据此声称卡产生因果改进。|
|样本限制|三家为开发集，问项跟随上一轮答案生成。分母分别给出计划、实际启动、正式交付和完成评分轮数。模型未尝试/受预算截断与研究能力分开报告。评分者是离线复核的 Codex 子代理；报告保留后续人工复核所需出处。|
